# Issue 83 Phase 1 provenance review

Status: **in progress; neither Phase 1A nor Phase 1B has passed its gate** (September 28, 2026). Phase 0 approved the intended bundle policy, not a particular binary payload. The current installer remains Python-only. This is an engineering provenance review, not legal clearance or a release lock.

The reproducible *candidate* records are [tool assets](ISSUE83_TOOL_CANDIDATES.json) and [Python wheels](ISSUE83_WHEEL_CANDIDATES.json). They contain exact filenames, upstream URLs, release versions, SHA-256 values, wheel metadata, and native-file/notice inventories where inspected. Separate [CPython](ISSUE83_CPYTHON_NATIVE_PROVENANCE.md) and [Deno](ISSUE83_DENO_PROVENANCE.md) native-input records clarify their source chains. Do not feed these candidates directly into release packaging: none is a reviewed full input lock, and several entries are explicitly rejected below. Downloaded archives and probe output remain in ignored `tmp/issue83-artifacts/` and are not committed.

## Phase 1B — Python wheels

The candidate manifest enumerates 26 direct/transitive packages from the current local environment against Windows x64 CPython 3.13 wheel tags. Each archive was downloaded, SHA-256-checked against PyPI, and inspected for dependency metadata, native files, and notice filenames. All 26 cached hashes were rechecked; 31 active dependency edges have no missing or unsatisfied version constraints. The [isolated local Python 3.13 probe](ISSUE83_PHASE1_LOCAL_PROBE.md) ran imports, synthetic media decoding, and offline CPU inference. A newer [native-wheel review](ISSUE83_PHASE1B_NATIVE_REVIEW.md) installed the candidate set into the official full private Python 3.13.15 runtime and repeated offline CPU inference with an audited local cuDNN-omission transformation. This remains a candidate set, not an approved `--require-hashes` release lock or clean-host test; versions originally came from the local Python 3.14 environment.

Two candidate wheels need distinct treatment before release:

- `av==18.1.0` advertises BSD-3-Clause metadata, but its downloaded `cp311-abi3-win_amd64` wheel contains 74 `.dll`/`.pyd` files, including FFmpeg and `libx264`/`libx265` DLLs. The [PyAV upstream issue](https://github.com/PyAV-Org/PyAV/issues/2270) independently identifies the GPL-enabled FFmpeg wheel concern. **Provisional path A selected:** investigate the published wheel under applicable GPL obligations for the combined Python processing program while preserving the project's own MIT source license where compatible. The isolated runtime probe passed; exact corresponding source, notices, and in-process licensing review remain open. Do not describe this payload as MIT-only.
- The PyAV wheel also includes Intel's oneVPL dispatcher, distinct from a GPU runtime, and the pinned FFmpeg build enables it for Quick Sync. Temporarily removing the DLL made `import av` fail; the original DLL was restored and hash-checked. Retaining it is compatible with a no-optional-GPU-**runtime** interpretation of Phase 0, subject to a complete source/notice and native-behavior audit. A no-GPU-interface requirement would instead need a different/rebuilt PyAV wheel. See the [local probe record](ISSUE83_PHASE1_LOCAL_PROBE.md).
- `ctranslate2==4.8.1` `cp313-win_amd64` wheel contains `ctranslate2/cudnn64_9.dll` and no wheel notice file. **The as-shipped wheel remains outside Phase 0's no-GPU-runtime scope.** A [hash-checked transformation](../scripts/issue83_cpu_wheel.py) now omits that one DLL, rewrites/validates `RECORD`, and yields byte-identical outputs in two local runs; its transformed wheel passed offline CPU `large-v3` inference under the full private Python 3.13.15. The upstream Windows build recipe itself specifies `WITH_CUDNN=OFF` but copies the DLL into the wheel. Intel OpenMP, oneMKL/oneDNN, Microsoft runtime, and remaining source/notice obligations are still open. See the [native review](ISSUE83_PHASE1B_NATIVE_REVIEW.md).

Other unresolved inventory items include 26 wheel packages' native libraries, pip's vendored packages, exact corresponding source for distributions without an sdist (including CTranslate2, faster-whisper, flatbuffers, and onnxruntime), and the actual license/notice text—not merely metadata labels or filenames. Preserve any LGPL replacement/relinking rights required by the selected native libraries. Do not infer that a dependency's Python-package license covers its bundled DLLs. The [candidate manifest](ISSUE83_WHEEL_CANDIDATES.json) records all inspected names; it is evidence for the next decision, not authority to ship.

Phase 1B remaining gate work: approve and audit path A's GPL-enabled PyAV/native source set, including oneVPL and x265; resolve Intel OpenMP/oneMKL/oneDNN distribution and nested notices; resolve the `MSVCP140.dll` clean-host prerequisite; finish native/source/notice mappings for ONNX Runtime, NumPy/OpenBLAS, tokenizer/HF-Xet, pip/setuptools vendors, and the remaining wheels; and produce the reviewed release input lock. The cuDNN-omission transformation and local target-Python CPU operation are now proven, but **the Python inputs are not approved** until those other checks pass. Phase 3 audits the assembled cuDNN-free payload; Phase 7 tests the actual installer on a clean Windows host.

## Validation and release boundary

Archive hashes and executable probes above were performed locally. Offline recheck of all 26 cached wheel hashes and 8 tool-asset hashes matched the candidate records. The wheel-inspection regression test passed; the full backend suite passed (368 tests) at the initial Phase 1 checkpoint and 383 tests with the new probe/contract tests. The later [isolated target-interpreter probe](ISSUE83_PHASE1_LOCAL_PROBE.md) passed imports, synthetic media decoding, and CPU transcription with and without the bundled cuDNN DLL. A separate libvpl-omission probe failed at PyAV import, as expected for a linked native dependency. Actual private-release-Python, assembled-payload, packaged-app, and clean-host installer validation have not run; those belong to Phases 3, 6, and 7, not the Phase 1 input gate.

The inspection scripts only inspect upstream candidates and do not change packaging, desktop runtime selection, model downloads, or user media. The existing packaging/audit rules must remain Python-only until a future phase supplies a fully reviewed input lock, source companion, notices, and tests. Phase 8's codec patent decision remains separate.
