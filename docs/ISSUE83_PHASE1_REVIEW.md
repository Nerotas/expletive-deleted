## Phase 1B — Python wheels

The candidate manifest enumerates 26 direct/transitive packages from the current local environment against Windows x64 CPython 3.13 wheel tags. Each archive was downloaded, SHA-256-checked against PyPI, and inspected for dependency metadata, native files, and notice filenames. There are no missing default-extra dependency edges among these candidates. This is not a resolver-generated or approved `--require-hashes` lock: package versions came from the local Python 3.14 environment, wheel availability does not demonstrate import compatibility, and the target Python 3.13 runtime has not run them.

Two candidate wheels conflict with the approved scope or desired distribution terms:

- `av==18.1.0` advertises BSD-3-Clause metadata, but its downloaded `cp311-abi3-win_amd64` wheel contains 74 `.dll`/`.pyd` files, including FFmpeg and `libx264`/`libx265` DLLs. The [PyAV upstream issue](https://github.com/PyAV-Org/PyAV/issues/2270) independently identifies the GPL-enabled FFmpeg wheel concern. **Reject this candidate** pending a compatible PyAV build with separately reviewed LGPL-compatible FFmpeg libraries or an explicit program-license decision. Its in-process linkage needs separate review; the separate FFmpeg executable decision does not settle it.
- `ctranslate2==4.8.1` `cp313-win_amd64` wheel contains `ctranslate2/cudnn64_9.dll` and no wheel notice file. **Reject this candidate** under Phase 0's no-GPU-runtime scope. The [upstream build options](https://github.com/OpenNMT/CTranslate2/blob/master/docs/installation.md) allow a CPU-only build; produce and inspect one, including its CPU math-library and compiler-runtime dependencies.

Other unresolved inventory items include 26 wheel packages' native libraries, pip's vendored packages, exact corresponding source for distributions without an sdist (including CTranslate2, faster-whisper, flatbuffers, and onnxruntime), and the actual license/notice text—not merely metadata labels or filenames. Preserve any LGPL replacement/relinking rights required by the selected native libraries. Do not infer that a dependency's Python-package license covers its bundled DLLs. The [candidate manifest](ISSUE83_WHEEL_CANDIDATES.json) records all inspected names; it is evidence for the next decision, not authority to ship.

Phase 1B remaining gate work: obtain or build approved CPU-only CTranslate2 and compatible PyAV/FFmpeg wheels; resolve and hash the complete wheel set including pip; map every native dependency to exact license, notice, and matching source; validate a clean Windows CPython 3.13 install, imports, and supported CPU transcription with no CUDA/cuDNN download. **The Python payload is not approved** until those checks pass.

## Validation and release boundary

Archive hashes and executable probes above were performed locally. Offline recheck of all 26 cached wheel hashes and 8 tool-asset hashes matched the candidate records. The wheel-inspection regression test passed; the full backend suite passed (368 tests). Script bytecode compilation and `git diff --check` passed. No target CPython 3.13 clean-runtime, packaged-app, or frontend validation was performed: those remain open gates, not implicit successes.

The inspection scripts only inspect upstream candidates and do not change packaging, desktop runtime selection, model downloads, or user media. The existing packaging/audit rules must remain Python-only until a future phase supplies a fully reviewed input lock, source companion, notices, and tests. Phase 8's codec patent decision remains separate.
